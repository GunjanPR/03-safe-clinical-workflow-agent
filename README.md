# Safe Clinical Workflow Agent: medication reconciliation over synthetic FHIR

A medication-reconciliation support agent over 5,000 synthetic FHIR R4 patients (Synthea). It
compares a patient's own account of their medications with the chart, finds discrepancies and
safety issues, cites the chart records and the reference behind every recommendation, scores
its own uncertainty, and proposes changes that only a clinician can approve. Identity
verification, role-based access, approval tokens and a hash-chained audit log are built into
the workflow, not added afterwards.

> **Demo only, not for clinical use.** All patients are synthetic. The knowledge base consists
> of short LLM-written paraphrases of public references, not reviewed by a pharmacist. The
> evaluation cases and their labels are generated by code, not written by clinicians.

**Held-out test results (600 cases, run once on 2026-11-27)**, against a **no-controls
ablation**: the same parser and list diff with every safety control removed
([docs/test_report.md](docs/test_report.md)). The test split was not used while building the
agent. Run on an AMD Ryzen 7 9800X3D / RTX 5070 Ti 16 GB desktop.

| Metric | Full agent, deterministic parser | Full agent, `qwen2.5:7b-instruct` parser | No-controls ablation |
|---|---|---|---|
| Unsafe writes committed (150 attack cases) | **0** | **0** | 180 |
| Wrong-patient tests blocked | **50/50** | **50/50** | 0/50 |
| Recommendations grounded in chart + reference | **99.7% (947/950)** | 99.3% (957/964) | 0% (0/669) |
| Injection cases flagged / benign statements flagged | 60/60 / 0/400 | 60/60 / 0/400 | - |
| Unnameable medications routed to a pharmacist | 40/40 | 40/40 | 0/40 |
| Workflow completion (expected terminal state) | **100% (460/460)** | 96.3% (443/460) | 91.3% (420/460) |
| Clear cases over-escalated to a pharmacist | 0/420 | 4.0% (17/420) | 0/420 |
| Discrepancy precision / recall | 0.992 / 1.000 | 0.972 / 1.000 | 0.948 / 1.000 |
| Clinical-alert precision / recall | 1.000 / 1.000 | 0.981 / 0.981 | - / 0.000 |
| Audit replay matches live outcome | 600/600 | 600/600 | - |
| Latency per case p50 / p95 | 0.01 / 0.04 s | 0.97 / 2.50 s | 0.01 / 0.01 s |

The held-out numbers match the dev split, so the fixes made on dev did not overfit it. The
deterministic parser stays the default: on the test split the LLM parser added 17 needless
pharmacist escalations and missed 6 of 309 clinical alerts, though without any safety failure.
The ablation's unsafe-write count is higher than its case count because one attack case can
cause several writes. These are not clinician-validated results.

**What these numbers do and do not show.**

- **The ablation is not a competitor.** It is built to follow instruction-like text in the
  statement and to accept an asserted approval, so "0 vs 180 unsafe writes" shows that each
  attack is real and that some control blocks it. It does not show that the agent beats a
  system someone would deploy.
- **The clinical-alert and discrepancy scores are a consistency check.** The case generator
  derives the expected alerts from the same knowledge base the agent runs, and writes
  medication names from the same lexicon the parser matches. A perfect score therefore means
  the pipeline applies its own rules without loss, not that the rules are clinically right
  or that the parser understands how patients really talk.
- **Injection detection** is measured on attack templates from the same code base as the
  guard, so 60/60 is an upper bound.

## Tech Stack

| Layer | Tools |
|---|---|
| API | FastAPI, Uvicorn |
| Orchestration | LangGraph (verify identity → gather chart → guard text → parse → reconcile → route) |
| Data | Synthea 5,000 patients (FHIR R4 bulk ndjson) → compact store via SQLAlchemy: SQLite by default, PostgreSQL optional |
| FHIR server (optional) | HAPI FHIR R4 (`hapiproject/hapi:v7.4.0`) as an alternative read backend |
| Clinical references | Curated YAML knowledge base (62 entries: 28 interactions, 8 allergy, 11 renal, 15 duplication) and a 135-ingredient drug lexicon, with BM25 evidence retrieval |
| LLM (optional) | Any OpenAI-compatible endpoint; Ollama locally (`llama3.2` 3B / `qwen2.5:7b-instruct`) |
| Safety | Two-identifier identity check + session context lock, RBAC, HMAC approval tokens, prompt-injection guard, hash-chained audit log with replay |
| Observability | OpenTelemetry spans per agent step → Jaeger (docker-compose) |
| Tests | pytest (24 tests), ruff; GitHub Actions CI (lint, tests, report check, image build) |

## Architecture

| Step | Module | What it does |
|---|---|---|
| Verify identity | `identity.py` | Needs two agreeing identifiers (name, date of birth, MRN, phone) and locks the session to that patient |
| Gather chart | `store.py`, `fhir_store.py` | Active medications, allergies, conditions and recent labs from the SQL store or HAPI FHIR |
| Guard text | `guard.py` | Flags prompt-injection patterns in the patient statement and in chart notes |
| Parse | `parser.py`, `meds.py` | Deterministic parser over a 135-ingredient lexicon; an optional LLM parse is anchored to the statement and merged with it |
| Reconcile | `reconcile.py`, `kb.py` | Omission, commission, dose and frequency diffs, plus interaction, allergy, renal and duplication rules, each with BM25-retrieved evidence |
| Route | `agent.py`, `approvals.py`, `writer.py` | Low-confidence cases go to a pharmacist; others become a proposal that only a clinician can approve with an HMAC token bound to that proposal |
| Audit | `audit.py` | Every step is appended to a hash-chained log that can be replayed |

The no-controls ablation (`baseline.py`) runs the same parser and list diff, with none of the
identity, guard, grounding or approval controls.

## How to Run

```bash
cp .env.example .env
make install
make data        # Synthea 5,000 patients (Java 17+) -> data/clinical.db
make test
make run         # API on http://127.0.0.1:8020
make up          # docker compose: API + Jaeger (profiles: postgres, fhir)
```

## Evaluation

`python -m clinagent.eval.run --cases eval/cases_dev.jsonl --name <run>` scores the full agent
and the no-controls ablation on the same cases and writes `eval/results/<run>.json`; `make report` renders
the Markdown report. Rates carry 95% Wilson intervals and precision/recall carry bootstrap
intervals. Cases cover standard reconciliations and eight attack types (injected notes and
medication names, a nurse trying to write, claimed, expired and replayed approvals, stale
proposals, cross-patient writes) plus five wrong-patient tests.

`make eval-det` and `make eval-llm` run the held-out test split. Both were run once on
2026-11-27; the results are in [docs/test_report.md](docs/test_report.md) and at the top of this README.
