# Safe Clinical Workflow Agent: medication reconciliation over synthetic FHIR

A medication-reconciliation support agent over 5,000 synthetic FHIR R4 patients (Synthea). It
compares a patient's own account of their medications with the chart, finds discrepancies and
safety issues, cites the chart records and the reference behind every recommendation, scores
its own uncertainty, and proposes changes that only a clinician can approve. Identity
verification, role-based access, approval tokens and a hash-chained audit log are built into
the workflow, not added afterwards.

> **Demo only, not for clinical use.** All patients are synthetic. The knowledge base consists
> of short paraphrases of public references, written by an AI (Claude) and not reviewed by a
> pharmacist. The evaluation cases and their labels were also generated by code written by
> Claude, not by clinicians.

> **Status: in progress.** The results below are from the 150-case **dev** split, which was
> also used to fix the parser, matcher and verifier, so they are not held-out numbers. The
> 600-case test split (`eval/cases_test.jsonl`) has not been run yet.

**Dev-split results (150 cases, deterministic parser)**, against a baseline that uses the same
parser and list diff without the safety layer ([docs/dev_report.md](docs/dev_report.md)):

| Metric | Full agent | Baseline |
|---|---|---|
| Unsafe writes committed (33 attack cases) | **0** | 40 |
| Wrong-patient tests blocked | **10/10** | 0/10 |
| Recommendations grounded in chart + reference | **100% (269/269)** | 0% (0/181) |
| Injection cases flagged / benign statements flagged | 15/15 / 0/107 | - |
| Unnameable medications routed to a pharmacist | 11/11 | 0/11 |
| Workflow completion (expected terminal state) | 100% (122/122) | 91.0% (111/122) |
| Audit replay matches live outcome | 150/150 | - |
| Latency per case p50 / p95 | 0.02 / 0.09 s | 0.02 / 0.04 s |

With an LLM parser (`qwen2.5:7b-instruct` via Ollama), completion falls to 93.4%, 7.2% of
clear cases are over-escalated to a pharmacist, and p95 latency is 25.5 s
([docs/dev_report_qwen.md](docs/dev_report_qwen.md)). The safety results are unchanged: 0
unsafe writes and 10/10 wrong-patient tests blocked.

## Tech Stack

| Layer | Tools |
|---|---|
| API | FastAPI, Uvicorn |
| Orchestration | LangGraph (verify identity → gather chart → guard text → parse → reconcile → route) |
| Data | Synthea 5,000 patients (FHIR R4 bulk ndjson) → compact store via SQLAlchemy: SQLite by default, PostgreSQL optional |
| FHIR server (optional) | HAPI FHIR R4 (`hapiproject/hapi:v7.4.0`) as an alternative read backend |
| Clinical references | Curated YAML knowledge base (62 entries: 28 interactions, 8 allergy, 11 renal, 15 duplication) and a 135-ingredient drug lexicon, with BM25 evidence retrieval |
| LLM (optional) | Any OpenAI-compatible endpoint; Ollama locally (`llama3.2` 3B / `qwen2.5:7b-instruct`) |
| Safety | Two-identifier identity check + session context lock, RBAC, HMAC approval tokens, prompt-injection guard, hash-chained audit log with replay |
| Observability | OpenTelemetry spans per agent step → Jaeger (docker-compose) |
| Tests | pytest (24 tests), ruff |

## Architecture

| Step | Module | What it does |
|---|---|---|
| Verify identity | `identity.py` | Needs two agreeing identifiers (name, date of birth, MRN, phone) and locks the session to that patient |
| Gather chart | `store.py`, `fhir_store.py` | Active medications, allergies, conditions and recent labs from the SQL store or HAPI FHIR |
| Guard text | `guard.py` | Flags prompt-injection patterns in the patient statement and in chart notes |
| Parse | `parser.py`, `meds.py` | Deterministic parser over a 135-ingredient lexicon; an optional LLM parse is anchored to the statement and merged with it |
| Reconcile | `reconcile.py`, `kb.py` | Omission, commission, dose and frequency diffs, plus interaction, allergy, renal and duplication rules, each with BM25-retrieved evidence |
| Route | `agent.py`, `approvals.py`, `writer.py` | Low-confidence cases go to a pharmacist; others become a proposal that only a clinician can approve with an HMAC token bound to that proposal |
| Audit | `audit.py` | Every step is appended to a hash-chained log that can be replayed |

The baseline (`baseline.py`) runs the same parser and list diff, with none of the identity,
guard, grounding or approval controls.

## How to Run

```bash
cp .env.example .env
make install
make data        # Synthea 5,000 patients (Java 17+) -> data/clinical.db
make test
make run         # API on http://127.0.0.1:8020
make up          # docker compose: API + Jaeger (profiles: postgres, fhir)
```

## Evaluation

`python -m clinagent.eval.run --cases eval/cases_dev.jsonl --name <run>` scores the full agent
and the baseline on the same cases and writes `eval/results/<run>.json`; `make report` renders
the Markdown report. Rates carry 95% Wilson intervals and precision/recall carry bootstrap
intervals. Cases cover standard reconciliations and eight attack types (injected notes and
medication names, a nurse trying to write, claimed, expired and replayed approvals, stale
proposals, cross-patient writes) plus five wrong-patient tests.

`make eval-det` and `make eval-llm` run the held-out test split. They have not been run yet.
